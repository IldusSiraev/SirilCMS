## What this is

SirilCMS — headless CMS for landing sites: page builder from blocks + themes + forms. Non-developer content managers assemble sites in the admin from pre-built blocks, switch themes, and build forms — no deploys. Public site is SSR with caching. pnpm workspace monorepo.

| Path | Role | Port |
|---|---|---|
| `packages/contracts` | `@sirilcms/contracts` — SSOT: block/theme/form-field contracts (types, registry, `to-payload.ts`, `resolve.ts`) | — |
| `packages/web` | `@sirilcms/web` — Nuxt module: runtime UI (blocks, layouts), server middleware/cache/purge API | — |
| `packages/admin` | `@sirilcms/admin` — Payload extension: collections/endpoints/access/admin-ui + canonical migrations | — |
| `apps/reference-web` | `@sirilcms/reference-web` — public site: thin Nuxt 4 reference app (`nuxt build`), cache, purge API | 3000 |
| `apps/reference-admin` | `@sirilcms/reference-admin` — builder: thin Payload 3 app on Next.js 16 (payload.config, seed), PostgreSQL | 3001 |
| `e2e` | Playwright golden-path spec: create page in admin → publish → verify on site → verify cache purge | — |
| `infra` | docker-compose (dev/prod), Caddy, scripts, Makefile | 80/443 (prod) |
| `docs` | developer guide, runbooks (dev/prod), specs/plans | — |

## Commands

```bash
pnpm install
pnpm dev:pg                                # Postgres 16 via docker, or waits for external pg on :5433
pnpm --filter @sirilcms/reference-admin migrate   # apply Payload migrations
pnpm seed                                  # demo content (idempotent — skips if sites already exist)
pnpm dev:all                               # web :3000 + admin :3001 (runs dev:pg first)
pnpm test                                  # all tests (pnpm -r --no-bail test)
pnpm lint                                  # ESLint across the whole monorepo (root eslint.config.mjs)
pnpm typecheck                             # tsc --noEmit (packages + reference-admin) / nuxt typecheck (reference-web)
```

Single-workspace test runs (all use vitest):

```bash
pnpm --filter @sirilcms/contracts test
pnpm --filter @sirilcms/admin test
pnpm --filter @sirilcms/web test
```

E2E (Playwright, separate from `pnpm test` — needs a real Postgres, builds+starts both apps, not run as part of the fast unit-test loop):

```bash
docker run -d --rm -p 5432:5432 -e POSTGRES_USER=payload -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=payload postgres:16
PAYLOAD_DB_URI=postgresql://payload:dev@localhost:5432/payload PAYLOAD_SECRET=<32+ chars> pnpm --filter @sirilcms/reference-admin migrate
pnpm --filter e2e exec playwright install --with-deps chromium   # once
PAYLOAD_DB_URI=postgresql://payload:dev@localhost:5432/payload pnpm --filter e2e test:e2e
```

Block/theme changes require a Payload migration:

```bash
pnpm --filter @sirilcms/reference-admin migrate:generate   # new migration file in packages/admin/src/migrations
pnpm --filter @sirilcms/reference-admin migrate            # apply
pnpm --filter @sirilcms/reference-admin generate:types     # regenerate payload-types.ts after schema changes
```

Build: `pnpm -r build` (reference-web → `nuxt build`, reference-admin → `next build`).

Admin login (after seed): `owner@demo.ru` / `admin123` at `http://localhost:3001/admin` (`/` is a placeholder, not a bug).

Windows: `pnpm` may be missing from PATH — use `& "$env:APPDATA\npm\pnpm.cmd" ...`.

## Architecture

Data flow:

```
Admin (Payload UI) → Postgres → Nuxt (server-side $fetch to Payload REST, NO auth, published-only)
    → BlockRenderer (blockType+variant → Vue SFC) → HTML (5 min cache)
Publish → afterChange hook → POST web/api/purge (Bearer) → cache cleared
```

Rules that must not be violated:

- Public reads carry no auth token; the published/draft filter is enforced server-side in the web module. Exception: `/preview/*` routes forward the editor's own Payload JWT (from `admin.preview`'s `token`, `packages/admin/src/collections/{pages,posts}.ts`) to read drafts — same `access.read` rules apply, no new bypass.
- Page cache: `packages/web/src/runtime/server/middleware/cache.ts` (HTML, 5 min TTL, `x-siril-cache` header). `/preview/*` is excluded from this cache — never cache draft content.
- Purge: `packages/admin/src/utils/publish-hook.ts` (afterChange hook, fire-and-forget `POST {NUXT_URL}/api/purge` with `Bearer PURGE_TOKEN`, body `{ siteId }`). Draft saves do **not** purge — only publish does. Purge is per-site: clears only the published site's cache, not the whole install (falls back to a full purge if `siteId` is missing or its domain doesn't resolve).
- Role `owner` has full access; `editor` is restricted to their own site via `canScope` in `packages/admin/src/access/site-scope.ts`.
- The first user created in an empty DB can self-register without auth — if created without explicit `role: owner` it becomes `editor`, leaving no admin. Seed always sets `role: owner` explicitly for the first user.

### Blocks — the SSOT pattern

A block = one contract in `packages/contracts/src/registry.ts` (`BLOCKS`, append-only) + auto-generated Payload fields (`packages/contracts/src/to-payload.ts`) + a Vue SFC + optional theme config. See [docs/developer.md §4](docs/developer.md) for the full walkthrough and field-type mapping table.

- `variants[0]` in a block's contract is the fallback variant.
- Vue component path: `packages/web/src/runtime/app/blocks/<type>/<Variant>.vue`, filename is PascalCase variant id (`default` → `Default.vue`). No manual registration — `packages/web/src/module.ts` builds the block registry from module blocks plus a project glob `app/blocks/**/*.vue` (project overlay, e.g. `apps/reference-web/app/blocks`, project wins). Missing component → renders `Placeholder.vue`, never crashes.
- New/changed contract fields require a new migration (`pages.sections` is a Payload `blocks` field; each block type gets union'd fields per variant via `admin.dependencies`).
- `resolveVariant` (`packages/contracts/src/resolve.ts`) falls back to the first theme-allowed variant when a block/variant is disabled or unknown for the active theme — content is never lost, only degrades visually.

### Themes — two synchronized locations

Every theme needs both, kept in sync:
1. JS tokens: `THEMES[]` in `packages/contracts/src/registry.ts` (consumed via `getTheme(id).tokens` → inline `:style` in every block component).
2. CSS file: `packages/web/src/runtime/themes/<id>/tokens.css` (project apps can override per theme via an app-root `themes/<id>/tokens.css` glob), injected into `<head>` by `packages/web/src/runtime/app/layouts/default.vue` via `useHead`.

Switching `Sites.theme` in the admin is a data change — applies instantly, no deploy, triggers cache purge.

### Known gotchas (see [docs/developer.md §6](docs/developer.md) for full list)

- `<style>`/`<script>` inside a `<template>` block in a Vue client component is a hard `vite:vue` error — use `useHead({ style: [...] })` for dynamic CSS instead.
- Payload rich-text fields must use `minimalRichTextEditor` from `packages/contracts/src/to-payload.ts`; `editor: 'true'` as a string crashes.
- A theme missing `tokens.css` silently falls back to the default theme's CSS file at build time.
