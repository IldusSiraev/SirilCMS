## What this is

SirilCMS — headless CMS for landing sites: page builder from blocks + themes + forms. Non-developer content managers assemble sites in the admin from pre-built blocks, switch themes, and build forms — no deploys. Public site is SSR with caching. pnpm workspace monorepo.

| Path | Role | Port |
|---|---|---|
| `apps/web` | Public site: Nuxt 4 (SSR/Nitro), cache, purge API | 3000 |
| `apps/admin` | Builder: Payload 3 on Next.js 16, PostgreSQL | 3001 |
| `packages/blocks-definitions` | SSOT: block/theme/form-field contracts (types, registry, Payload mapper, resolve) | — |
| `infra` | docker-compose (dev/prod), Caddy, scripts, Makefile | 80/443 (prod) |
| `docs` | developer guide, runbooks (dev/prod), specs/plans | — |

Full architecture/administration reference: [docs/developer.md](docs/developer.md). Ops runbooks: [docs/runbooks/dev.md](docs/runbooks/dev.md), [docs/runbooks/prod.md](docs/runbooks/prod.md).

**`apps/admin` runs Next.js 16** — breaking changes vs. training data. Read [apps/admin/AGENTS.md](apps/admin/AGENTS.md) (points into `node_modules/next/dist/docs/`) before writing Next.js code there; it's auto-regenerated by `next dev`, keep it committed.

## Commands

```bash
pnpm install
pnpm dev:pg                                # Postgres 16 via docker, or waits for external pg on :5433
pnpm --filter @siril/admin migrate         # apply Payload migrations
pnpm seed                                  # demo content (idempotent — skips if sites already exist)
pnpm dev:all                               # web :3000 + admin :3001 (runs dev:pg first)
pnpm test                                  # all tests (pnpm -r --no-bail test)
pnpm lint                                  # ESLint across the whole monorepo (root eslint.config.mjs)
pnpm typecheck                             # tsc --noEmit (admin, blocks-definitions) / nuxt typecheck (web)
```

Single-workspace test runs (all use vitest):

```bash
pnpm --filter @siril/blocks-definitions test
pnpm --filter @siril/admin test
pnpm --filter @siril/web test
```

Block/theme changes require a Payload migration:

```bash
pnpm --filter @siril/admin migrate:generate   # new migration file in src/migrations
pnpm --filter @siril/admin migrate            # apply
pnpm --filter @siril/admin generate:types     # regenerate payload-types.ts after schema changes
```

Build: `pnpm -r build` (web → `nuxt build`, admin → `next build`).

Admin login (after seed): `owner@demo.ru` / `admin123` at `http://localhost:3001/admin` (`/` is a placeholder, not a bug).

Windows: `pnpm` may be missing from PATH — use `& "$env:APPDATA\npm\pnpm.cmd" ...`.

## Architecture

Data flow:

```
Admin (Payload UI) → Postgres → Nuxt (server-side $fetch to Payload REST, NO auth, published-only)
    → BlockRenderer (blockType+variant → Vue SFC) → HTML (5 min cache)
Publish → afterChange hook → POST web/api/purge (Bearer) → cache cleared
```

Rules that must not be violated:

- Public reads carry no auth token; the published/draft filter is enforced server-side in the web app. Exception: `/preview/*` routes forward the editor's own Payload JWT (from `admin.preview`'s `token`, `apps/admin/src/collections/{pages,posts}.ts`) to read drafts — same `access.read` rules apply, no new bypass.
- Page cache: `apps/web/server/middleware/cache.ts` (HTML, 5 min TTL, `x-siril-cache` header). `/preview/*` is excluded from this cache — never cache draft content.
- Purge: `apps/admin/src/utils/publish-hook.ts` (afterChange hook, fire-and-forget `POST {NUXT_URL}/api/purge` with `Bearer PURGE_TOKEN`). Draft saves do **not** purge — only publish does.
- Role `owner` has full access; `editor` is restricted to their own site via `canScope` in `apps/admin/src/access/site-scope.ts`.
- The first user created in an empty DB can self-register without auth — if created without explicit `role: owner` it becomes `editor`, leaving no admin. Seed always sets `role: owner` explicitly for the first user.

### Blocks — the SSOT pattern

A block = one contract in `packages/blocks-definitions/src/registry.ts` (`BLOCKS`, append-only) + auto-generated Payload fields (`to-payload.ts`) + a Vue SFC + optional theme config. See [docs/developer.md §4](docs/developer.md) for the full walkthrough and field-type mapping table.

- `variants[0]` in a block's contract is the fallback variant.
- Vue component path: `apps/web/app/blocks/<type>/<Variant>.vue`, filename is PascalCase variant id (`default` → `Default.vue`). No manual registration — `apps/web/app/blocks/registry.ts` globs `./**/*.vue`. Missing component → renders `Placeholder.vue`, never crashes.
- New/changed contract fields require a new migration (`pages.sections` is a Payload `blocks` field; each block type gets union'd fields per variant via `admin.dependencies`).
- `resolveVariant` (`packages/blocks-definitions/src/resolve.ts`) falls back to the first theme-allowed variant when a block/variant is disabled or unknown for the active theme — content is never lost, only degrades visually.

### Themes — two synchronized locations

Every theme needs both, kept in sync:
1. JS tokens: `THEMES[]` in `packages/blocks-definitions/src/registry.ts` (consumed via `getTheme(id).tokens` → inline `:style` in every block component).
2. CSS file: `apps/web/themes/<id>/tokens.css`, glob-imported and injected into `<head>` by `apps/web/app/layouts/default.vue` via `useHead`.

Switching `Sites.theme` in the admin is a data change — applies instantly, no deploy, triggers cache purge.

### Known gotchas (see [docs/developer.md §6](docs/developer.md) for full list)

- `<style>`/`<script>` inside a `<template>` block in a Vue client component is a hard `vite:vue` error — use `useHead({ style: [...] })` for dynamic CSS instead.
- Payload rich-text fields must use `minimalRichTextEditor` from `to-payload.ts`; `editor: 'true'` as a string crashes.
- A theme missing `tokens.css` silently falls back to the default theme's CSS file at build time.
