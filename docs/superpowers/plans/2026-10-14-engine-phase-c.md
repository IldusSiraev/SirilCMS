## Находка при первой же установке пакетов вне монорепо (C0)

Релиз 0.5.0 **непригоден** для проекта вне монорепо — проверено установкой `pnpm pack`-tarball'ов в копию `examples/minimal-project`:

1. `payload migrate/generate:*` падает: `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING` (Node не стрипает типы в `node_modules`; в монорепо работало, потому что симлинк резолвится вне `node_modules`).
2. `next build` без `transpilePackages` — `Unknown module type`; с ним — type-check падает на импорте `../../../../apps/reference-admin/payload-types` из кода пакета.
3. `nuxt build` — Nitro не транспилирует `src/runtime/server/**/*.ts` из `node_modules`.

Решение B6 «публиковать TS-исходники» было ошибочным → **C0: компилировать `@sirilcms/web` (`@nuxt/module-builder`) и `@sirilcms/admin` (`unbuild`/mkdist) в `dist`**; выпускать 0.6.0.

## C4 — результаты пилота (2026-10-15)

**Проект:** `D:\Projects\playground\dev-portfolio` (вне репозитория движка), создан `npx @sirilcms/create-siril@0.7.0` **из реестра**. Исходник — клиентский `index.html` (700 строк, Tailwind v4 CDN, «чертёжный лист», 4 кейса).

**Что получилось:** 9 кастомных блоков (`dev-intro`, `symptom-list`, `work-intro`, `case-screen`, `case-flow`, `case-migration`, `case-adr`, `principles`, `contact-sheet`), тема `dev-portfolio`, лэйаут-override (шапка/подвал клиента), Tailwind v4 вместо CDN-прототипа, seed с контентом клиента (`admin/src/scripts/seed.ts`), проектная миграция. Весь контент редактируется в админке.

**Проверка 1:1:** текст страницы совпадает с оригиналом слово в слово (кроме одной намеренной разницы: в десктопной шапке 4-й пункт «§1 Когда меня зовут» — навигация из `SiteContent` общая для шапки, мобильного меню и подвала; в оригинале в десктопной шапке только 3 пункта). Высота страницы на 1280px — **8145 px в обоих**, высоты шапки/подвала/каждого из 4 кейсов совпадают до пикселя. Production-сборка: аннотации (hover), мобильное меню, копирование адреса работают. Цикл «правка в админке → публикация → purge → сайт» проверен.

**Время:** от начала работы над макетом до закоммиченного, проверенного проекта — ~27 минут (с чтением макета и исправлением найденных ошибок движка). Это работа с ИИ-ассистентом на простом статичном макете: сравнение с «1–3 дня» ручного конвейера прямое, но не строгое.

**Ошибки движка, найденные пилотом (исправлены/в работе):**
1. `@sirilcms/web@0.7.0`: Nuxt загружал `dist/runtime/**/*.d.ts` как плагины → приложение не гидрировалось (SSR нормальный; template-freshness это не ловил). Фикс + CI-проверка — PR #55.
2. Payload генерирует миграции с `import { MigrateUpArgs … }`, на котором `migrate` падает → автоправка в шаблоне (`fix-migration-imports.mjs`).
3. Подпись блока в редакторе брала `slug` («Dev Intro»), а не `name` контракта → исправлено.

**Не сделано/ограничения:** развёртывание (Docker-образы проекта, прод-сервер) и обновление движка в пилоте через extension-api §5 (критерий приёмки C) — следующий шаг, нужен релиз с фиксом #1; репозиторий пилота не опубликован (только локальный git).
